# PM 项目导图真实实测与 0.12.1 最小修复

用户明确要求以 PM 投稿项目测试原生项目导图。目标为其已登记的 AsymAudit 中枢，保留论文、数据、投稿状态和人工正文。

发现：原项目事件查询在真实文库中连续超过单请求 5 秒时限；内核版本及项目块均正常可读。等价的属性候选集合查询约 0.2 秒返回 31 个事件；修复后使用相同默认 5 秒客户端，完整快照约 2.5 秒完成，最慢单请求约 0.52 秒。

修复仅替换一个事件 SQL：分别按项目及事件类型配对筛选，以 UNION 去重后按块标识读取。保留列、created DESC 排序、LIMIT 501 和后续权限及完整性检查。不调高超时、不加入缓存、不修订项目事实。

另发现既有项目状态投影落后于事件流，导图严格预检按设计拒绝生成，返回 writeAttempted=false；回读确认进度页属性未变，也没有登记导图根块。项目事实与源清单对账须单独明确范围，本补丁不修改项目内容或降低该保护。

现有项目与导图相关测试 5 项通过；完整 91 文件、975 项测试通过，插件、服务器、MCP App、Agent Kit、CLI 构建通过。独立复核对照 SQLite 验证两类事件筛选语义一致。安装并重载补丁后，正式 MCP 的完整项目快照约 1.9 秒返回，状态为 ready。所有笔记写入继续沿用 Sisyphus MCP 严格预检。

## 0.12.2 真实验收补充

用户明确授权先核对最新交付材料，再更新共享项目进度并生成导图。进度页与中枢更新前均已创建可恢复文档快照；原阶段记录、知识引用和论文文件保留。

真实预检与更新中又定位三处最小修复：普通关系记录挤占知识成果窗口；内核刷新来源锚文本及截断末尾空格引发虚假人工修改冲突；根块 HTML 属性顺序变化引发严格预检状态漂移。修复分别限定为窗口前筛选、同来源当前生成文本比对与去除未使用的根块 DOM 状态，不新增后台任务、缓存或第二套实现。独立复核通过。

正式思源 3.8.8／Sisyphus 0.12.2 实测创建一张 54 节点原生导图，47 个节点引用源块；包含圆角连线、节点样式、两条关系与两层嵌套概要。提交项目状态属性后返回 mindmapSync=updated，原根块与存续节点标识、显示配置保留。严格重复同步返回 unchanged、transactionState=no_change，前后状态散列一致；完整节点正文与层级回读通过，项目诊断为空。

完整 91 文件、976 项测试通过；插件、服务器、MCP App、Agent Kit 与 CLI 构建通过。本轮未重新逐页验收论文、重算研究或执行投稿；自动更新限定于 Sisyphus 项目角色写入／状态提交与来源事件，不监听任意本地文件变化。

## 0.12.3 同步性能验收

将逐块 DOM 读取改为内核原生批量接口，任一返回块缺失或为空即停止；直接子块结构检查使用已有并发池，最多六项。单次计划读取的 DOM 请求由 114 次降为 1 次，保留全部段落签名、引用与层级检查。该接口经官方 3.8.6、3.8.8 源码及活动 3.8.8 实例核对，不提高基础版本门槛。

无变化结果跳过处理器内额外回读与整页刷新，外层严格预检、状态漂移检查和写后状态回读保持。真实内容或显示变更继续完整核验并刷新，不使用缓存或新的后台任务。

同一张 54 节点导图在正式 MCP 上：优化前预检 5.645 秒、无变化同步 30.168 秒，合计 35.814 秒；0.12.3 预检 3.065 秒、无变化同步 18.051 秒，合计 21.116 秒，单次实测减少约 41%。返回 unchanged／no_change，前后状态散列一致，响应无页面刷新操作。仍是约二十秒的完整严格流程，不承诺首次新建只需数秒。

回读确认圆角连线、两条关系、两层概要及 54 个节点保留。现有测试中增加并发上限和单次批量读取断言；91 文件、976 项测试全部通过，独立复核通过，插件及 CLI 同源构建通过。本机先备份 0.12.2 再覆盖构建产物并重载，保留已有配置。
