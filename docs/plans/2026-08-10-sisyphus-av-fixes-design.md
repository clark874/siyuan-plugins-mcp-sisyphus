# Sisyphus 数据库接口修复设计

## 背景

当前 `av.render` 能从思源内核读取选择项和资源字段，但统一响应精简层会递归删除数组元素中的 `content`，导致 `mSelect` 只剩颜色、`mAsset` 丢失资源路径。思源内核已经支持 `setAttrViewName`，现有 MCP 却没有暴露数据库重命名操作。

## 设计

1. 响应精简继续删除普通搜索结果和通用数组项中的大段 `content`。
2. 精简过程传递父字段名，仅为 `mSelect` 与 `mAsset` 数组元素保留 `content`；不放宽其他响应。
3. 新增 `av(action="rename", avID, name, blockID?)`：
   - 权限和事务上下文只接受镜像接口、`type='av'` 的 SQL 记录或 DOM 验证通过的真实数据库块，不使用绑定行的源内容块；
   - 调用 `setAttrViewName` 事务；
   - 读取旧名称和数据库块原 `updated`，写入完整撤销事务；
   - 更新数据库所属块的 `updated`，并沿用现有界面刷新机制。

## 验证

- 单元测试覆盖选择项、资源值以及普通内容仍被精简的边界。
- 单元测试覆盖重命名参数、权限上下文、事务、撤销事务和返回值。
- 执行完整测试与生产构建。
- 部署前备份本地安装目录，重载插件后在真实思源数据库中完成写入、回读、重命名和还原验证。
