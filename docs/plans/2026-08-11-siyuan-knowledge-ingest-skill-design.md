# 思源知识摄取 Skill 设计

## 目标

把人类网页剪藏与 Agent 主动检索收束到同一条可重复执行的知识摄取管线。外部网页只作为来源，不直接等同于成熟知识；正式写入前必须检查既有主题中枢、来源网址、内容重复和版本冲突，写入后必须通过块回读与 SQL 复核。

首个验收样本为 Scattertext 的 GitHub 仓库、spaCy Universe 项目页和 Penn Libraries 教程。试验必须复用既有《00 Scattertext方法与项目知识中枢》和 `Scattertext知识资产总表`，不得按链接机械创建三篇完整剪藏笔记。

## 架构边界

知识摄取分为五层：

1. 浏览器或 Agent 获取网页正文与元数据；
2. SQL 与全文检索定位既有主题、来源和关联块；
3. Agent 对来源执行 `SKIP`、`REGISTER`、`MERGE`、`UPDATE`、`CREATE`、`CONFLICT` 或 `DEPRECATE` 决策；
4. MCP 的文档、块、属性、AV 与时间线接口实施可恢复写入；
5. SQL、块读取和 AV 渲染共同验证结果，并以相同输入复跑确认幂等性。

SQL 只承担写入前盘点、候选定位和写入后审计，不承担语义裁决或写入。AV 用作面向人的来源与资产控制台；为弥补 AV 单元格无法与引用图直接 SQL 联结的边界，每个正式来源块同时保存最小 SQL 可见属性：`custom-source-url`、`custom-source-hash`、`custom-source-checked`、`custom-ingest-status` 和 `custom-topic`。

## Skill 契约

Skill 接受主题、一个或多个网址、可选目标中枢、来源预算和运行模式。默认模式为审阅合并；用户已明确授权写入时可以直接实施，但仍须先生成内部差量计划并建立时间线保护节点。

每个来源必须输出：规范网址、来源类型、权威等级、抓取时间、来源版本、内容哈希、既有命中、处理决策、目标块和核验状态。相同规范网址与相同内容哈希再次运行时不得创建新块或新数据库行。

规范网址仅接受 `http:` 与 `https:`，拒绝内嵌凭据，并对查询参数执行白名单处理：仅保留经过审计的版本、语言、分页和视图类语义字段，其他字段默认删除；访问令牌、签名、会话票据与未知认证字段不能进入来源属性。正文哈希不包含抓取 frontmatter，避免抓取时间和追踪参数变化制造伪更新。辅助脚本以 `skills/source/normalize-source.mjs` 为唯一源，由生成器同步到 MCP 与 CLI Skill，并作为 Skills-over-MCP 附加资源发布摘要。

来源块采用可恢复的两阶段写入：首次追加的可见正文必须同时包含规范网址和正文哈希，随后才写块属性与 AV 行。若属性写入失败，必须保留追加返回的稳定块 ID 并原位修复；返回值丢失时先以正文双标识寻找孤儿块，不得重新追加。`auto-trusted` 的权威身份必须由来源外的项目根域、软件包登记或已核验组织关系确认，且只能自动执行低风险登记与合并。

## Scattertext 样本决策

- GitHub 仓库：作为官方技术来源，登记 0.2.3、Python 3.11 要求、当前紧凑语料与缩放示例，并明确 PyPI 发布状态需要独立核验；不再新建完整教程。
- spaCy Universe：作为生态目录与最小示例来源，仅登记定位和适用规模；不新建独立笔记。
- Penn Libraries：作为机构教程来源，合并现有知识库缺失的短语提取、语料特征性与效应量说明；保留教程中的版本和命名误差风险，不把教程内容视为现行 API 的唯一依据。

## 验收条件

- MCP 与 CLI 均生成并可安装知识摄取 Skill；
- MCP 资源、Prompt 和 Skills 扩展能够读取该 Skill；
- Skills 扩展同时发布规范化脚本资源及 SHA-256 摘要，两套生成副本不可漂移；
- 三个来源都在既有中枢中形成可追溯来源块，并进入现有 AV；
- 每个来源块具有完整的最小来源属性；
- 中枢正文只包含差量知识，不包含三份整页复制；
- SQL 能查询到三个规范网址和核验状态；
- AV 行数由 32 增至 35，且三行字段可回读；
- 相同输入复跑不产生新块或新行；
- 全量测试、生产构建和真实思源回读通过。
