# v0.9.3 Agent 会话溯源契约

## 目标

在任何支持 Sisyphus 的 Agent 中触发项目知识化时，记录原始讨论会话、执行编译会话、知识化事件和目标知识原子之间的可查询关系。此后，任一 Agent 均可按项目列出全部相关会话，并获得与客户端能力相匹配的原生链接、统一启动链接或恢复命令。

## 数据模型

采用“项目 → 会话 → 知识化事件 → 知识原子”四层模型：

- 项目中枢块是全部溯源记录的父块；
- 会话记录块按 `projectId + provider + hostAlias + sessionId` 唯一；
- 事件记录块按 `projectId + eventId` 唯一，并通过真实块引用连接会话记录与知识原子；
- 知识原子只保存最近一次事件摘要，完整历史由事件记录块承担。

来源会话与编译会话必须分离。交互式知识化时两者通常相同；定时编译或跨 Agent 转交时，两者可以不同。

## 属性契约

会话记录块：

- `custom-provenance-kind=session`
- `custom-provenance-schema=1`
- `custom-provenance-project-id`
- `custom-provenance-provider`
- `custom-provenance-session-id`
- `custom-provenance-host-alias`
- `custom-provenance-capture-method`
- `custom-provenance-link-capability`
- `custom-provenance-first-seen-at`
- `custom-provenance-last-seen-at`

事件记录块：

- `custom-provenance-kind=event`
- `custom-provenance-schema=1`
- `custom-provenance-project-id`
- `custom-provenance-event-id`
- `custom-provenance-operation`
- `custom-provenance-occurred-at`
- 来源会话与编译会话的 provider、session id、host alias、capture method
- `custom-provenance-target-atom-ids`，值为 JSON 数组
- 可选 `custom-automation-id`

知识原子最近摘要：

- `custom-source-session`、`custom-source-provider`
- `custom-compile-session`、`custom-compile-provider`
- `custom-provenance-event`、`custom-provenance-project-id`
- `custom-provenance-updated-at`
- 可选 `custom-automation-id`

## 聚合工具动作

`provenance` 工具提供六个动作：

1. `register_session`：幂等登记或刷新一个 Agent 会话；
2. `record_event`：登记来源/编译会话，创建事件记录，并更新目标原子的最近摘要；
3. `list_project_sessions`：按项目汇总各 Agent 会话及其链接能力；
4. `list_atom_events`：列出某个知识原子的全部知识化事件；
5. `resolve_session_link`：解析原生链接、统一启动链接和恢复命令；
6. `validate_session`：在本机可验证范围内检查会话是否仍可恢复。

## 链接能力分级

- `native`：客户端具有已核验的原生深链，例如 `codex://threads/<id>`；
- `launcher`：使用 Sisyphus 统一启动链接，由适配器转交目标客户端；
- `resume_command`：只能提供本机恢复命令；
- `unavailable`：仅保留会话标识，当前没有可靠打开方式。

统一启动链接格式：

`siyuan://plugins/siyuan-plugins-mcp-sisyphus/?action=open-agent-session&provider=<provider>&sessionId=<sessionId>&hostAlias=<hostAlias>`

不得把未经验证的 URI 宣称为原生深链。返回结果必须明确 `linkCapability`，调用方据此决定是否渲染为“一键打开”。

## 捕获规则

会话标识由发起知识化的 Agent 侧捕获并显式传入。优先级如下：

1. 客户端注入的会话环境变量，标记为 `environment`；
2. 客户端公开的会话上下文或钩子参数，标记为 `client_context`；
3. 用户显式提供，标记为 `explicit`；
4. 按最近修改时间推断 rollout，仅作为兼容路径，标记为 `inferred_latest_rollout`，并返回风险提示。

MCP 服务端不得用“最新文件”猜测调用方身份，因为多个 Agent 可并发调用同一服务端。

## 一致性与幂等

- 写动作受严格写入协调器保护，必须携带 `requestId` 与当前状态哈希；
- 同一会话键重复登记只刷新 `last-seen-at`；
- 同一事件键重复写入不得创建第二个事件块，而应补齐目标原子摘要；
- `record_event` 先建立完整事件记录，再更新原子摘要。后半段失败时，事件记录仍可作为恢复依据；
- 创建或更新后必须读取块属性核验关键字段。

## 边界

- 本期定位到会话，不定位到具体消息 offset；
- 不对存量原子进行全量模糊回填；
- session id 是增强溯源指针，知识原子仍须保持自包含；
- 本机 rollout 被清理后，历史记录仍可列出，但验证状态可能变为 `missing`；
- 跨设备只保存 `hostAlias`，不把物理目录写入思源属性。

## 发布验收

- Codex 环境变量捕获并写入真实思源项目；
- ZCode 或兼容 rollout 会话以显式/推断方式写入，并明确捕获方法；
- 第三个独立调用端按项目列出两类会话，得到不同 provider、session id、链接能力与验证状态；
- 从知识原子反查事件，从事件块的真实块引用回到会话记录和原子；
- 重复执行同一 `eventId` 不产生重复记录；
- 全量单元测试、构建、Agent Kit 生成、插件热重载和发布资产校验通过。
