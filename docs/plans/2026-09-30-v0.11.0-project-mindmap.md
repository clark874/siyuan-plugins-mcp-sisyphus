# Sisyphus 0.11.0 升级方案

## 目标与范围

面向思源 3.8.6 增加项目原生思维导图，复用现有项目快照、事件和状态投影。导图是事实的显示投影，不是第二份项目权威记录。修复新块类型重复读取，同时对齐检索类型。保留现有认证、原生工具白名单和文本知识治理边界。

## 用户行为

- 首次明确调用 `project.sync_mindmap(projectId=...)`，在既有项目进度页生成一张原生导图并启用该项目的自动同步。
- 节点包括项目概览、阶段与工作线、快照窗口内的知识成果、权威产物、最近更新和诊断；引用源块，内容来自实时快照，不推断未登记成果。
- 经 Sisyphus 登记事件或提交项目正文、状态属性后同步已启用的导图。历史补录遵守事实时间排序，迟到事件不倒退当前状态。
- 无变化不写入；已有节点保持块 ID。人工修改受管理节点、增加节点或改变结构时停止同步并报告冲突。备注放在导图之外。
- 原生显示设置与内容分开；增量更新保留根块和存续节点上的折叠、样式、关系与概要配置。

## 最小实现

1. 原生 `mindmap` / `mindmap_item` 的读取、Kramdown 清理和类型过滤适配。
2. 一个项目同步动作，复用严格写入预检、请求幂等账本和权限校验；单事务创建或增量更新导图与管理记录；结构变化更新原有容器并保留存续项 DOM，不使用孤立导图项插入。
3. 在现有事件和状态投影写入完成后调用同步，仅处理已启用项目；失败不撤销项目事实，明确返回待同步状态。
4. 同步更新技能源、帮助、版本、变更记录与发布包；官方 `data/ai/AGENTS.md` 与插件虚拟 `/AGENTS.md` 只说明来源区别，不自动合并。

## 非目标

不监听任意本地文件、不启动后台轮询、不批量迁移现有导图、不开放集市写入或图片能力，不安装新框架或测试基础设施。

## 验收与发布

- 一条新类型读取主路径回归；一条项目生成、增量同步及重复执行主路径；一条人工修改失败路径。复用相关既有测试与完整发布检查。
- 导图仅在内核 3.8.6 及以上执行；旧内核保持原有工具，返回升级提示。
- 验收严格预检不写入、请求重放不重复、权限与来源变化保护、原生节点类型及回读。
- 插件版本 0.11.0；CLI 同源构建版本提升至 0.4.20。构建插件、Agent Kit 和 CLI，核对归档内容与 SHA-256。
- 用户自行升级思源。发布证据与目标机器的实际版本分别记录，未完成的 3.8.6 实机检查不得表述为通过。
- 发布 GitHub 版本及可下载资产并更新稳定通道；不自动执行不可逆的 npm 包发布。

## 使用与升级次序

1. 思源升级到 3.8.6；安装本次 `package.zip`，重启插件并重新连接 MCP，让客户端读取新工具清单。原有 Token 和权限配置继续使用。
2. 对已经登记来源且有唯一进度页的项目，调用 `project.snapshot` 核对项目身份和诊断。来源不可用、时间线截断、状态落后或进度页重复时先处理具体缺口。
3. 以 `action=sync_mindmap`、`projectId`、`validateOnly=true` 预检；复制返回的 `issuedRequestId` 和 `stateHash`，以同一业务参数加 `requestId`、`expectedStateHash` 执行。不要自行构造请求标识或用旧预检凭据。
4. 首次生成后自动同步已启用项目。正文或结构人工冲突、来源变化、权限撤回等会明确返回待同步；不自动覆盖人工修改。需要停用时，以同一严格流程执行 `autoSync=false`。

导图分组与快照窗口固定，知识节点最多三十项、最近事件最多十项，完整项目事实仍以快照和源块为准。本地文件更新、正式笔记界面编辑及其他客户端的写入不会直接触发本插件；须经现有项目工作流提交，或显式同步。

## 更新影响判断

| 3.8.6 变化 | 本插件处理 |
| --- | --- |
| 原生思维导图块 | 必须修复容器读取，并增加本次项目同步能力 |
| 原生导图显示配置 | 保留原有根块、存续项 DOM 与显示元数据，不重建整张图 |
| 官方 MCP 认证与 Agent 指令文件 | 维持单一外部 Sisyphus 网关和既有 Token；明确各自指令来源 |
| 本次 Zotero DOI 导入修复 | 修复位于批次脚本，保持 Zotero 只读网关；不是本次插件发版依据 |

本次发版依据是原生块兼容修复和已验收的项目导图新能力。发布后更新稳定通道的真实资产哈希；保留上一版本下载入口供回退。插件升级与正式项目启用导图分别执行，不批量改写现有项目。
