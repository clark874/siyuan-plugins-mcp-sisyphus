# Sisyphus 思源工作区控制面设计

## 目标与边界

本轮升级把现有 Sisyphus MCP 扩展为思源工作区的受控控制面，使代理能够盘点、读取、解释和修改与知识组织直接相关的核心状态，并能对每次修改进行确认、核验、审计与回滚。

控制面覆盖以下对象：

- 已安装插件及其启用状态、版本、兼容性与更新信息；
- CSS、JavaScript 代码片段的摘要、受限内容读取与受控修改；
- 已安装插件专属存储目录中的安全文本配置；
- 编辑器、导出、文档树、搜索、快捷键、外观、闪卡和代码片段等低风险系统设置；
- 变更计划、执行记录、快照和回滚结果。

以下边界永久排除：

- 账户、登录、访问鉴权、同步、仓库、加密和密钥管理；
- AI 密钥、令牌、Cookie、密码、私钥、环境变量与原始秘密值；
- 任意工作区文件系统访问和跨插件目录访问；
- 无法精确恢复的物理删除；
- 会削弱安全确认、访问控制或数据保护的全局设置。

控制面的目标是覆盖可安全建模的核心工作流，不以机械暴露思源全部 HTTP 接口为目标。

## 工具结构

继续使用现有 `system` 聚合工具，以减少顶层工具数量，并复用权限配置、帮助资源、工具发现和危险动作确认机制。

### 读取与解释动作

- `get_plugin`：读取单个插件的精简元数据、启用状态和可用存储根映射。
- `list_plugin_updates`：列出可更新插件及当前版本与目标版本。
- `list_snippets`：分页列出代码片段，默认只返回长度、哈希、类型和启用状态。
- `list_plugin_storage`：在受限深度和数量内列出插件专属存储目录。
- `read_plugin_storage`：读取允许的文本配置，执行大小限制、截断和敏感信息遮蔽。
- `inspect_plugin`：结合通用解释器与声明式适配器，输出功能开关、作用范围、时间调度、外观、集成和未知字段等结构化解释。
- `list_control_changes`：分页列出变更计划和已执行变更的精简审计记录。
- `get_control_change`：读取单项计划或变更的脱敏详情。

### 两阶段修改动作

- `plan_change`：读取当前状态，验证目标与期望状态，生成脱敏差异和有期限的计划，不修改目标对象。
- `apply_change`：按计划编号重新读取当前状态；仅当状态哈希未漂移时，在 MCP 危险动作确认后执行并核验。
- `rollback_change`：按变更编号恢复执行前状态，在危险动作确认后执行并核验。
- `discard_change_plan`：删除尚未执行的计划记录，不影响目标对象。

`apply_change` 与 `rollback_change` 纳入 `DANGEROUS_ACTIONS`。`plan_change` 虽会保存控制面内部记录，但不修改思源目标状态，保持非危险动作分类。

## 变更类型

`plan_change` 使用判别联合输入，首轮支持：

1. `plugin_state`：启用或禁用插件；回滚时恢复原启用状态。
2. `snippet_upsert`：新增或完整更新代码片段；保存修改前的完整片段集合。
3. `snippet_remove`：移除指定片段；保存修改前的完整片段集合。
4. `plugin_storage_write`：写入安全文本配置；保存原内容和原文件存在状态。
5. `plugin_install`：安装新插件或按明确仓库版本更新；保存当前安装元数据。
6. `plugin_uninstall`：卸载插件；仅在可获得精确仓库地址和版本哈希时允许生成计划。
7. `setting_patch`：对允许的设置分区进行深合并；保存修改前的完整分区。

数组在设置补丁中整体替换，对象递归合并。任何包含敏感键名、疑似秘密内容、禁止分区或安全确认削弱字段的输入均在计划阶段拒绝。

## 状态机与持久化

控制面记录存放在插件自己的思源 API 文件空间：

```text
/data/storage/petal/siyuan-plugins-mcp-sisyphus/control-plane/
├── plans/<planID>.json
└── changes/<changeID>.json
```

计划状态为 `planned | applied | discarded | expired`；变更状态为 `applied | rolled_back | rollback_failed | verification_failed`。

计划至少保存：创建和过期时间、变更类型、目标标识、脱敏期望状态、执行前状态哈希、风险摘要和差异摘要。执行记录至少保存：来源计划、执行时间、脱敏前后快照、核验结果、回滚能力和回滚状态。

每项记录单独存储，避免并发追加日志的覆盖风险。内部记录也执行输出脱敏；允许回滚所需的原值仅限本插件自己的受控存储，且在任何 MCP 响应中不得返回原始秘密。

## 执行与回滚流程

```mermaid
flowchart LR
    A["读取目标当前状态"] --> B["验证边界并生成计划"]
    B --> C["保存计划与状态哈希"]
    C --> D["危险动作确认"]
    D --> E["重新读取并校验哈希"]
    E -->|"一致"| F["执行修改"]
    E -->|"漂移"| X["拒绝执行并要求重新规划"]
    F --> G["回读核验"]
    G -->|"成功"| H["保存变更记录"]
    G -->|"失败"| I["立即尝试恢复前状态"]
    H --> J["可按变更编号回滚"]
    J --> K["回读核验回滚结果"]
```

执行期间不信任计划生成时的状态。`apply_change` 必须重新计算目标状态哈希，发现任何漂移即停止。修改完成后必须通过官方接口回读；核验失败时立即尝试恢复执行前状态，并如实记录恢复结果。

插件安装、更新和卸载只在能构造精确逆操作时开放：新安装可由卸载回滚；更新和卸载必须保存原 `repoURL`、`repoHash` 和启用状态，并能按原哈希重新安装。缺少精确版本信息时拒绝规划。

## 插件存储隔离

通用插件存储根严格限定为：

```text
/data/storage/petal/<已安装插件名称>/
```

声明式适配器可登记经过核对的别名，例如 `kmind-plugin` 对应 `kmind`、`knote-plugin` 对应 `knote`。调用方不能自行指定根目录。

路径验证规则：

- 拒绝绝对路径、反斜杠、空字节、空段、`.` 和 `..`；
- 逐段通过思源 `readDir` 检查，拒绝任何符号链接；
- 限制递归深度、返回条目数、单文件大小和总输出长度；
- 二进制、数据库、压缩包和疑似凭据文件只返回安全元数据或直接拒绝；
- JSON 递归遮蔽敏感键，普通文本按敏感模式遮蔽；
- 不提供关闭遮蔽或返回原始秘密的参数。

底层读取采用流式限额，在完整内容进入内存前检查 `Content-Length` 并按字节中止超限响应。

## 代码片段与设置保护

代码片段列表默认不返回正文，只返回 SHA-256、字符数、类型、名称和启用状态。受限读取仍执行截断和敏感信息遮蔽。写入内容若包含令牌、密码、Cookie、私钥或其他高置信秘密模式，则拒绝生成计划。

设置只允许以下分区：

- `editor`
- `export`
- `fileTree`
- `search`
- `keymap`
- `appearance`
- `flashcard`
- `snippet`

账户、API、AI、鉴权、发布、同步、仓库、加密、变量和系统级分区均不暴露。允许分区内部仍使用递归敏感键拦截表，并禁止关闭删除确认、只读保护或其他安全约束。

## 插件解释器

解释层采用“通用解释器 + 声明式适配器注册表”：

- 通用解释器根据字段名和数据类型识别功能开关、路径与范围、时间与调度、外观、集成和高级参数；
- 适配器只声明已核对的存储别名、候选配置文件、字段说明和安全可写范围；
- 未识别字段必须单独列出，不把推断写成确定语义；
- 不承诺理解任意第三方插件的全部运行时状态。

首批适配已安装且知识组织价值较高的插件：`Calendar-heatmap`、`graph-enhance`、`siyuan-plugins-index`、`syplugin-document-search`、`syplugin-hierarchyNavigate`、`siyuan-plugin-citation`、`siyuan-plugin-sidebar-memo`、`kmind-plugin` 和 `knote-plugin`。

## 模块划分

- `src/api/`：插件市场、插件运行状态、代码片段、设置和受限文件读取的薄封装。
- `src/control-plane/security.ts`：路径、文件类型、大小、敏感键和秘密内容校验。
- `src/control-plane/storage.ts`：计划与变更记录持久化。
- `src/control-plane/state.ts`：目标读取、规范化、哈希与核验。
- `src/control-plane/operations.ts`：规划、执行、逆操作和失败恢复。
- `src/control-plane/adapters.ts`：解释器注册表和通用解释逻辑。
- `src/tools/system/`：Zod 参数解析、动作路由和上下文紧凑响应。

业务逻辑不放入工具处理器，避免读取动作、执行动作和回滚动作之间复制安全校验。

## 验证与完成门槛

自动化测试至少覆盖：

- 插件、代码片段、设置和文件 API 封装；
- 路径穿越、符号链接、大小上限、二进制与敏感文件拒绝；
- JSON 和文本遮蔽、秘密写入拒绝；
- 计划过期、状态漂移、重复执行和非法回滚；
- 每种变更的成功执行、回读核验、失败恢复和显式回滚；
- 插件存储别名、通用解释与未知字段保留；
- 工具合同、帮助资源、权限默认值和危险动作分类；
- 完整测试套件、生产构建与 MCP 真实调用。

真实思源验收采用可恢复的临时片段或本插件测试配置完成“规划—执行—回读—回滚—再回读”闭环，不用用户的正式插件配置做破坏性试验。部署前备份当前安装目录，部署后重载插件并核对所有新增动作已由当前 HTTP MCP 服务暴露。

最终代码在 `codex/workspace-control-plane` 分支形成可追踪提交，标记本地维护版本标签并推送至用户的 GitHub Fork。稳定维护分支在完整验收前不被覆盖。
