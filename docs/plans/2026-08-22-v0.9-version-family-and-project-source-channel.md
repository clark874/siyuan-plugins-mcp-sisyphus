# Sisyphus 0.9 版本族与项目源文件通道规划

## 目标

0.9 版本族不再承载一次性的大规模治理重构。发布顺序遵循三个依赖层级：

1. 先保证客户端能够诊断连接、拒绝错误参数，并对关键写入给出可证明结果；
2. 再建立项目知识中枢、来源清单与本机项目目录之间的稳定映射；
3. 最后在显式登记的项目根目录内提供受控只读文件通道，并对既有项目执行一次完整补录审计。

批量附件导入、自动恢复点、文档/子树权限和自动引用阻断不与上述主线混发。

## 0.9.0 发布契约

### 纳入

- CLI 顶层 doctor 在 MCP 不可用时仍能区分内核、插件、网关、鉴权、initialize、tools/list 与 bootstrap 故障；
- launcher 不再把进程已 spawn 等同于 ready；
- 未知 flag、多余位置参数和错误 JSON 数组在调用前失败；
- 数组空值和重复项遵循 action 契约；
- CLI 在依赖模块求值前执行 Node 20 门禁；
- action help 显示 validateOnly、requestId、前置条件字段和可复制 CLI 示例；
- AV add_rows 未观察到 rowID 时返回 pending_verification 且禁止立即重试；
- AV set_cells 逐格回读；remove_rows 验证目标行消失。

### 明确排除

- Ledger v2 的 operationKey 和后台调和；
- system.get_write_status；
- av.inspect；
- 自动引用阻断；
- 自动时间线恢复点；
- 文档/子树权限；
- file.insert_assets 和 Markdown 导入；
- 项目源目录读取。

## 0.9.1 项目源登记模型

### 可迁移来源身份

项目知识中枢和来源清单至少保存：

- projectId；
- hubBlockId；
- manifestBlockId；
- sourceKind：git 或 directory；
- repository；
- revision 或目录快照指纹；
- relativePath；
- role：source、data、output、manuscript、evidence、config；
- hash；
- coverage：tracked、complete、curated 或 partial；
- exclusions 及其数量和理由。

本机绝对路径不得作为唯一来源身份。

### 本机绑定

绑定记录保存在插件受控存储中，不写入普通搜索结果：

- projectId；
- hostId；
- workspaceRoot；
- checkoutKind：git-clone、git-worktree 或 plain-directory；
- 当前 revision；
- verifiedAt；
- access：read-only 或 read-write；
- status：available、missing、stale 或 ambiguous。

### 文件清单分级

- A 级核心文件：逐文件保存路径、角色、版本和哈希，并允许后续建立知识原子；
- B 级一般文件：保存路径、类型、大小、修改时间和来源版本；
- C 级缓存/生成物：只保存排除规则、总量和聚合摘要。

完整清单进入插件管理的清单存储或项目 AV；项目中枢只保存摘要与正式引用，不粘贴数千行 Markdown。

### 建议动作

- file.register_project_source：显式登记或更新项目根目录；属于敏感本地路径操作，必须确认；
- file.scan_project_manifest：生成或增量刷新清单；只读取元数据和经策略允许的哈希；
- file.resolve_project_source：按 projectId 与 relativePath 解析，不读取内容；
- file.list_project_sources：分页列出项目和绑定状态。

0.9.1 不提供任意本地文件读取，也不自动把目录加入客户端工作空间。

## 0.9.2 受控只读文件通道

新增 file.read_project_source，仅允许：

- projectId 已登记且当前绑定为 available；
- relativePath 解析后仍位于真实根目录内；
- 拒绝 ..、绝对路径、符号链接越界和设备文件；
- 默认只读文本，限制扩展名、单文件字节数和返回字符数；
- 二进制文件只返回元数据和哈希；
- 普通知识搜索不暴露本机绝对路径；
- 所有结果区分 listed、readable、content_read 和 revision_verified；
- 不提供写入、删除、执行或自动工作空间扩权。

## 存量思源项目补录审计

审计在 0.9.2 发布并完成真实探针后执行。外部 AI 必须建立对象账本，状态按以下顺序推进：

发现项目中枢 → 读取中枢 → 确认 projectId → 确认来源清单 → 解析本机绑定 → 生成文件清单 → 补录缺失相对路径 → 回读 → 真实问答验收。

每个项目至少报告：

- 项目中枢稳定块 ID；
- projectId；
- 来源清单块 ID；
- 仓库、revision 或快照；
- 本机绑定状态；
- A/B/C 级文件数量；
- 未映射核心文件；
- 已登记但不可读文件；
- 过期、冲突和多绑定；
- 排除范围；
- 回读证据。

禁止事项：

- 不扫描用户主目录寻找候选项目；
- 不把缓存、忽略输出或文件存在本身升级为研究证据；
- 不把绝对路径作为唯一来源标识；
- 不将 mapped 报告为 readable；
- 不在没有精确分母时声称全部完成；
- 不整篇覆写含属性、引用或 AV 的项目文档。

可直接交付给外部 AI 的执行契约、账本字段和验收模板见
[`2026-08-22-existing-project-source-audit-playbook.md`](./2026-08-22-existing-project-source-audit-playbook.md)。该手册是 0.9.2 发布后的审计入口，不授权在 0.9.0 或 0.9.1 中绕过动作缺失自行扫描本机目录。

## 发布门

每个版本必须同时满足：

1. typecheck、全量测试、renderer/server/CLI/Agent Kit 构建通过；
2. 无 token 进入日志、包、配置样例或 Git；
3. 版本号在根包、plugin.json、包装器、delivery.json 与 Kimi 清单一致；
4. CLI 版本独立同步；
5. 真实 Sisyphus bootstrap 返回 schemaVersion=2、toolConfiguration.current=true；
6. 发布包解压检查和 SHA-256 校验通过；
7. CHANGELOG、README 与 Agent Kit 冷启动指令只描述实际已发布能力；
8. Git 标签和发布资产来自同一个已验收提交。
