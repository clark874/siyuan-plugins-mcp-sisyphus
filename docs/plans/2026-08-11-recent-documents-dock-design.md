# 最近修改侧边栏设计

## 目标

为 Sisyphus 增加一个与文档快照、文档差异相互独立的“最近修改”侧边栏。该视图解决深层文档更新后无法在分层文件树中整体上浮的问题，但不改变思源原生文件树排序，也不修改父文档更新时间。

## 数据源

侧边栏通过只读 SQL 分页读取 `blocks` 表中的文档根块，按 `updated DESC, id DESC` 稳定排序，并同时取得笔记本、完整人类路径、存储路径和精确更新时间。每页固定限制数量，自动分页受上限约束，更多历史由用户显式加载。

不使用 `/api/block/getRecentUpdatedBlocks` 作为主列表，因为该接口只返回最近 16 个段落块，一个集中编辑的文档会占满结果，不能稳定形成跨文档的最近修改视图。

## 界面与交互

- 注册独立 `LeftBottom` Dock 和独立时钟图标，默认关闭面板但显示侧边栏按钮。
- 顶部显示标题、搜索框、年月日粒度、更新类型筛选、目录聚合开关和刷新按钮。
- 每个条目显示文档标题、父级人类路径和更新时间。
- 点击条目通过思源 `openTab` 打开对应文档。
- 默认视图严格保持时间线；目录聚合是临时辅助选项，不写入插件设置。
- 目录聚合只在当前时间桶内部处理同一父文档下至少两篇子文档，组间顺序由组内最新文档决定，组内继续按更新时间降序排列；单篇与根文档保持原位。
- 思源的“目录”由父文档承担。父文档 ID 从文档存储路径的倒数第二级提取，聚合键同时包含笔记本 ID，避免跨笔记本同路径误合并。
- 目录箭头只负责展开与折叠，目录标题通过 `openTab` 直接打开父文档，不改变当前 Diff 选择。
- 面板仅在可见时加载；文档信息或文件树发生刷新时，使现有数据失效并在面板可见时重新读取。
- 空结果、加载失败和 SQL 元数据补充失败均有明确降级行为。

## 设置与生命周期

在既有 `versionControlSettings` 中增加 `recentDocumentsEnabled`，默认开启。该字段仅复用已存在的插件设置存储，不把最近修改功能并入时间线生命周期：关闭文档快照不影响最近修改侧边栏，关闭最近修改也不影响 MCP、CLI 或时间线。

插件卸载、运行时关闭开关和布局重建时，侧边栏组件、注册项、布局记录及按钮均应正确清理或重建。

## 测试与验收

1. 纯函数测试覆盖最近文档元数据合并、路径显示、时间格式与 SQL 降级。
2. 插件生命周期测试覆盖独立图标、Dock 注册、设置关闭、运行时移除、卸载和布局重建。
3. 组件源码契约测试覆盖原生最近文档接口、更新时间排序、批量 SQL、搜索、刷新与打开文档。
4. 通过全量测试、生产构建和当前思源实例实测；实测列表首项应与内核返回的最近更新 Scattertext 文档一致。
