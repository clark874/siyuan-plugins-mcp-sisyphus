# 思源集市只读目录设计

## 目标

在现有 `system` 聚合工具内补齐思源集市的只读发现能力，使 Agent 能够搜索可下载扩展包、精确读取包元数据，并在受限范围内阅读集市 README。安装、更新和卸载继续使用既有的计划、确认、核验与回滚控制面，不在浏览动作中产生任何状态变更。

## 动作设计

### `search_bazaar`

- 支持 `plugin`、`widget`、`theme`、`icon`、`template` 五类集市包。
- 支持关键词、安装状态、兼容状态、排序字段、排序方向和页码。
- 默认每页 20 项，最大 100 项。
- 返回名称、说明、版本、作者、仓库、仓库修订、兼容性、安装状态、更新时间、下载量、星标数和体积等紧凑字段。
- 不返回 README、图片正文或任意远程文件内容。

### `get_bazaar_package`

- 使用包类型与精确包名定位一个集市条目。
- 返回完整紧凑元数据、安装与更新状态以及后续安全动作提示。
- 精确匹配失败时给出使用 `search_bazaar` 缩小范围的可操作错误。

### `read_bazaar_readme`

- 先通过精确包名解析受信任的集市 `repoURL` 与 `repoHash`，调用思源内核 README 接口；调用者不能直接提交任意仓库地址。
- 把思源返回的 HTML 转换为纯文本，清除脚本、样式、标签、零宽字符和多余空白。
- 默认最多返回 12000 字符，最大 32000 字符；同时返回原始字符数、截断状态和 SHA-256。
- 不执行或渲染 README 中的脚本、嵌入对象和外部资源。

## 数据流与边界

所有数据经 `SiYuanClient` 调用思源 HTTP API，不直接访问工作空间文件系统。API 层只负责端点与参数映射；筛选、排序、分页、规范化和错误提示位于 `system` 处理层。新动作默认启用并归入基础只读能力，不加入危险动作集合。

## 测试与验证

- API 单元测试覆盖五类集市端点和 README 参数映射。
- 工具测试覆盖精确匹配、过滤、排序、分页、README 清洗与截断。
- action 合约、帮助快照、默认配置与界面映射必须同步。
- 完整测试、生产构建和真实 HTTP MCP 调用通过后才能部署。
- 真实验证只执行读取：分页搜索、单包详情和 README，不安装或更新任何包。
