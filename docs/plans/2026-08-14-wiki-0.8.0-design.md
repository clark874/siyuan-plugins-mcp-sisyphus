# Sisyphus `0.8.0-wiki.1` 设计说明

## 目标

本版本将 Sisyphus 明确推进为“思源 LLM Wiki 治理分支”，同时保持对上游 `v0.6.3` 的选择性兼容。

## 范围

### 纳入

1. `search.semantic`：提供思源 3.8 原生语义检索的低层、可控入口；现有 `search.knowledge` 继续承担引用折叠、命名原子优先与关联文档扩展。
2. `document.reorder` 与 `fs.reorder`：吸收上游同级文档排序能力。
3. 严格写入协调：写前探测、短期凭据、请求幂等、串行执行、写后回读与结果登记。
4. 原生 MCP 动作级白名单：只暴露对 Wiki 有价值的只读动作；任何未明确列出的动作默认拒绝。
5. 通用源码审计交接契约：验证外部审计方交付的清单、使用映射和基线信息，供后续知识编译消费。

### 不纳入

1. 不读取、比较或修改任何 textnets 源码、安装包或应用项目。
2. 不复制上游嵌入配置面板；思源 3.8 已提供官方配置、测试与重建索引界面。
3. 不引入 ChatGPT 隧道、图片生成、导入迁移等与本轮 Wiki 主线无关的功能。
4. 不把原生 MCP 的写操作转发给模型；所有笔记写入继续经过 Sisyphus 的权限、结构化资产保护与严格写入层。

## 调用分层

```text
自然语言问题
  ├─ search.semantic  → 原始语义候选（低层探针）
  └─ search.knowledge → 语义候选 + 引用折叠 + 原子优先 + 关联文档（默认 Wiki 入口）

写入请求
  → 权限检查
  → 结构化知识资产保护
  → 严格写入预检/幂等/串行化
  → 思源内核写入
  → 回读验证与登记
```

## 原生 MCP 策略

原生工具只有同时满足以下条件才可转发：

1. 工具名进入白名单；
2. 若工具存在 `action` 字段，动作也进入该工具的白名单；
3. 工具仍未被用户在设置中禁用；
4. 原生注册表声明为只读，或 Sisyphus 已通过固定策略证明该动作只读。

首批 Wiki 白名单：

- `search`：只读搜索动作；
- `ref`：反链、正向引用与引用关系读取；
- `outline`：文档大纲读取；
- `history`：列表、搜索与读取历史记录；
- `repo`：仓库列表、差异、搜索与文件读取；
- `image`：列表与分析，不含生成；
- `inbox`：列表与读取，不含转换和删除；
- `web_fetch`、`web_search`：保持现有只读开放网络能力。

未知动作一律失败关闭，并返回允许动作清单。

## 外部源码审计交接契约

插件只消费冻结产物，不自行重新比较源码。通用目录约定为：

```text
docs/source-audit/
  inventory.json
  usage-map.json
  baselines.md
```

`inventory.json` 的每条记录至少包含文件、符号或功能单元、行区间、行为差异、风险等级和证据哈希；`usage-map.json` 以项目为单位标注 `used`、`unused`、`obsolete` 或 `risky`；`baselines.md` 固定各基线提交号与哈希。插件提供结构校验与摘要，不推断源码结论。

## 验收门禁

1. 所有新增行为先有失败测试，再实现。
2. 原生白名单的每个写动作反例必须被拒绝。
3. 严格写入与结构化资产保护组合测试通过。
4. 全量单元、集成、CLI、生产构建通过。
5. 使用虚构源码审计夹具验证交接契约；不得依赖 textnets 文件。
6. 部署后仅做思源侧只读检索和临时纯 Markdown 写入抽检，测试数据必须清理。
