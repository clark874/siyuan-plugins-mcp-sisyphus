# 思源 3.8.7—3.8.8 兼容性与功能增量评估

日期：2026-10-21。

## 结论

建议安排 Sisyphus 0.11.2 兼容修复，但尚未修改版本或发布。导图、公式和引用主路径在 3.8.8 隔离内核中通过；数据库自动化新增的隐式写入未被插件现有笔记本权限门完整覆盖，已通过两条实际写入路径复现。因此撤回初步的“没有必要更新”判断；不能仅调整推荐版本后宣称全面兼容。

新增能力中，知识块自动收集和模板字段赋值具有最大的工作流增量；原生导图显示增强可以直接受益。先修复写入范围检查，再按实际使用需求增加受控入口，不为对齐上游而批量增加动作。

## 已确认的兼容问题：自动化扩大实际写入范围

### 复现一：AV 字段写入连带修改只读目标

1. 隔离工作区创建来源笔记本 A 和目标笔记本 B；来源数据库配置启用的 changed 规则，向 B 中数据库新增一行。
2. 将插件权限设为 A 可写、B 只读；首轮使用等价权限接口替身，其余均调用真实 3.8.8 HTTP 内核。
3. 使用当前 WriteSafetyCoordinator 和 callAvTool，执行同参数严格预检及 `av.set_cells`。
4. 预检通过，来源单元格回读通过，结果报告 `writeSafetyGuaranteed=true`；B 的行数从 0 增至 1。

这说明当前预检与回读覆盖来源状态，没有把自动化目标纳入插件权限范围。内核按已配置规则执行，不能据此声称内核自身的认证或加密边界失效。

### 复现二：普通块属性写入触发只读数据库收集

1. 在 B 的数据库设置启用的 block 收集规则，监听 A 中指定文档的段落，条件为 `custom-compat-collection=yes`。
2. 在隔离工作区通过 API 保存 A=rw、B=r，加载生产类 `PermissionManager`，实际断言 A 可写、B 不可写；本轮没有使用权限替身。
3. 使用当前严格协调器及块工具，向 A 的段落执行 `block.set_attrs`，使条件由不匹配变为匹配。
4. 严格预检通过、源属性写后回读通过、工具返回成功；B 中行数从 1 增至 2。

因此仅在 av.set_cells 上检查来源数据库的 automations 不能完整修复。官方收集路径观察 create、update、insert、delete、move、append、setAttrs 等事务；普通块、文档、项目导图及事件写入也需要按实际触发范围评估。

### 根因定位

- `src/core/write-safety-coordinator.ts` 的 AV 状态探针只读取传入 avID；最终权限检查从已收集状态和目标标识中提取笔记本。
- `src/tools/av/handlers.ts` 核验当前 AV 与其归属笔记本，set_cells 回读的是请求中的单元格。
- 思源 3.8.7—3.8.8 内核会在普通 API 事务中执行数据库规则；3.8.8 的块收集可在来源文档匹配后写入目标 AV。
- 同一加密边界限制不能替代 Sisyphus 的 r/rw/rwd 权限：两个普通笔记本处于同一加密边界，插件权限仍可不同。

## 新功能的实际增量

| 新功能 | 对现有用途的增量 | 采纳建议 |
| --- | --- | --- |
| 3.8.7 数据库自动化；3.8.8 块收集 | 将符合标签或自定义属性的知识块自动登记到知识索引，减少每轮手工维护 AV；保留源块引用 | 高价值，先修权限范围；不复制一套本地监听或轮询 |
| 3.8.8 模板字段赋值 | 根据触发时刻或源字段生成复查日期、文本状态、数值；计算后写入真实值 | 高价值；以后优先增加只读预览和规则诊断，实际规则写入另按必要性评估 |
| 导图关系箭头、概要、连线、布局 | 现有项目导图可保留并使用更清楚的关系显示、阶段分组和紧凑布局 | 当前可享受原生显示增强；本次不自动生成未经项目证据支持的关系或概要 |
| 嵌入并发与批次配置 | 使用原生语义索引时可按模型供应方限额调节索引吞吐 | 复用思源设置，不新增插件调度器；实际速度增益尚未测量 |
| 稳定插入当前编辑器选区 | 将侧栏生成内容发送到光标处更可靠 | 当前 MCP/CLI 以块 ID 定位，无紧迫迁移需求；有明确交互式写作需求再接入 |
| 锁定视图临时排序 | 以临时排序浏览研究台账，无须改共享排序 | 有实际排序需求时给既有 av.render 增加有界参数，不新建工具 |
| 位置、农历字段 | 适用于田野调查、历史日期或生活日程 | 当前通用文本知识工作流增量有限，按具体项目引入 |
| Gemini/DeepSeek 等原生 AI 接口 | 可能增强思源原生网页检索和抓取 | 保持现有只读白名单及来源核证，不添加第二套模型账户配置 |
| 图片、OCR、实况照片 | 超出现有文本知识治理边界 | 不接入 |
| Mermaid、KaTeX、编辑修复 | 现有文本、公式与图表显示可随内核更新获益 | 不为此新增 MCP 动作或重新封装渲染器 |

“完整块标识层级”主要是编辑器块标识显示改进，不应混同为新增一种持久块 ID 或 MCP 标识协议。列表项 ID 的实际保持情况已单独验证。

## 最小升级次序及验收门

1. **0.11.2 优先修复写入范围。** 在已有统一写入入口识别本次操作可能触发的启用规则，将派生目标纳入权限检查和预检凭据；同时处理 AV 触发与普通块收集。目标只读、不可访问或影响范围不能可靠核实则在发起写入前拒绝，明确指出自动化影响范围未核验。不要以写后告警替代写前阻断，不修改用户已配置规则，不默认关闭全部自动化。
2. **锁定当前缺陷。** 复用现有权限、严格写入和 AV 测试，增加最少量的允许写入与只读目标拒绝验证；两条隔离复现必须变为写前拒绝且源和目标均未变，同时无自动化的原路径正常。触发规则在预检后改变时必须使旧凭据失效。若内核当前接口不足以安全表达影响范围，先记录具体接口缺口，不声称完成全面兼容。
3. **兼容发布。** 修复通过、独立代码复核、现有全量检查和实际发布包验收后，才更新推荐版本至 3.8.8；本次尚未执行上述修复与发布。最低版本暂不提高，旧内核路径不因新增能力被强制关闭。
4. **功能增量。** 规则诊断、只读收集预览、模板预览和导图少量显示参数依次按实际需求加入；不把新功能配置器作为兼容修复的前提。
