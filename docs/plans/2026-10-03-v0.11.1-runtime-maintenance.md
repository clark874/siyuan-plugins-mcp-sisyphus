# 0.11.1 运行资源修复与发布审计

## 范围

仅修复响应完成后空闲 HTTP 连接无限存续，以及安全账本写入插件配置目录产生数据变更通知。保持 14 类工具、103 个 action；不修改 Hermes 配置、笔记正文、论文、权限或思源内核；不发布 npm 包。

## 根因与改动

1. `src/core/http-transport.ts` 原将 `keepAliveTimeout` 和 `timeout` 同时设为零。现在前者为 60 秒，后者保持零。计时从响应完成后开始，活动 SSE 不受该空闲期限影响。该改动不能代替 Hermes 自身的连接池治理，也不会强制关闭重复创建但尚未结束的 SSE。
2. `src/core/write-safety-ledger.ts` 原保存于 `/data/storage/petal/siyuan-plugins-mcp-sisyphus/writeSafetyLedger`。思源 3.8.6 的文件写入接口对该路径触发 `dataChanges`，而日志的 `reloads=[]`，属于配置变更通知，不是插件代码重载。现改为 `/data/storage/sisyphus-runtime/writeSafetyLedger`，仍经思源 API 同步写入。
3. 新账本缺失时读取旧账本，迁移成功后才允许依赖账本的操作；并发首次读取共享一次加载。旧文件保留，后续只写新位置。新文件损坏、非 404 API 错误或迁移写入失败均停止操作，不将其解释为空账本。有效期、容量、请求状态和元数据哈希保持不变。

## 恢复与降级

源码基线为 `6c62c1555eb7a0c6157306cacfe5f5a2319a008f`；旧版本的 GitHub 发布资产保持可用。安装使用现有 `agent-kit/scripts/update-sisyphus.mjs`，其备份目录为插件父目录下的 `.sisyphus-backups`，不使用会递归删除原插件的 `make-install`。

账本迁移保留旧文件，但它在迁移后不再更新。降级必须先停止写操作，通过思源 API 将新账本的最新记录同步回旧位置，再恢复旧插件并核对请求状态；仅恢复旧代码或旧账本副本不构成安全降级。未发生迁移或新写入时可直接恢复安装备份。

## 判读边界

45 条 `ESTABLISHED` 连接不能单凭状态判为泄漏；发布后应区分已结束响应的空闲连接与仍活动的 SSE。连接数量下降不能单独证明 CPU 或内存问题全部解决。此版本只消除已确认的两个资源放大因素，不承诺修复 Hermes 的客户端行为。
