# SQL 分析通道修复设计

## 背景

`search.query_sql` 会把内核返回的每一行交给笔记本权限过滤。聚合、`GROUP BY` 与递归 CTE 的结果通常不携带 `box`、`path` 或块 ID，现有实现无法解析其来源，因而把这些行全部当作无权限结果删除。带有 `id` 与 `box`、但没有 `path` 的普通结果又会先按 ID 逐行查询块归属，造成不必要的串行 HTTP 往返。最终结果还会被固定截断为 50 行。

## 安全边界

不能简单放行所有缺少来源字段的结果。查询者可以写出 `SELECT content FROM blocks`，故意隐藏 `box` 后绕过笔记本权限。修复采用保守规则：

1. 任意 SQL 可以伪造 `box` 或用另一个块 ID 掩盖内容来源，因此只要存在权限为 `none` 的笔记本，整个裸 `query_sql` 动作就保守拒绝；不再把结果列误当成可信数据来源。
2. 每次执行 SQL 前强制重载权限，避免刚设为 `none` 的笔记本在旧快照有效期间泄漏。全部笔记本均可读时，无须逐行解析归属，聚合、分组、CTE 和普通行全部直接返回。
3. 其他由 MCP 自己构造、来源可信的搜索和引用接口仍可复用行级权限过滤；带 `box` 的行直接判定，缺少直接笔记本字段的行使用有限并发解析。
4. SQL 仍只允许单条 `SELECT` 或主语句为 `SELECT` 的 CTE，不开放任何写入。

## 返回与分页

`query_sql` 新增 `maxRows`，默认返回至多 200 行，允许范围为 1—1000。SQL 本身仍应使用 `LIMIT/OFFSET` 控制内核工作量。响应补充无来源行的放行或过滤计数；发生过滤时返回明确警告，不再仅表现为空数组。

## 已知限制与后续方向

裸 SQL 的可用性与全局笔记本读取权限耦合：任意一个 `none` 都会关闭该动作。这是有意的保守安全边界，不是完整的行级安全。长期方案可以在可靠 SQL AST 基础上对每个相关表注入允许的 `box` 谓词，实现查询前行级安全；在正确覆盖子查询、CTE、JOIN、别名与嵌套表达式之前，不采用字符串拼接式改写。

## 验证

回归测试覆盖纯聚合、属性分组、递归 CTE、受限笔记本下的无来源内容行、100/300 行返回，以及带 `box` 结果不触发逐行归属查询。完成后运行全量测试、类型检查、生产构建和真实思源 MCP 对照查询。
