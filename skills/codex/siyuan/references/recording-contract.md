# 资料录入与项目接续

用户已授权维护项目的思源资料时，重要材料的保存与后续可调用性属于交付；只读询问、审阅、方案和无关聊天不写入。已明确授权的可恢复同范围工作不反复询问；新来源登记、敏感披露、不可逆操作仍遵守相应授权门。

## 资料、知识与现状分别交付

先列本轮新增或改变的全文、证明、代码、输出、裁决、失败边界和权威入口。每项注明应该保存的层次、已有对象、来源和未完成项，不能只挑容易摘要的内容。

| 对象 | 应保存什么 | 不能代替的验收 |
| --- | --- | --- |
| 资料副本 | 用户指定的完整方案、证明、材料，必要时包括完整代码；注明权威源与版本 | 全文包含、公式、表格和代码保真；保存成功不代表研究结论已核验 |
| 知识原子 | 能独立回答一个问题的决策、方法、证据或警告，指回资料中的对应位置 | name 返回承担回答的正文；有条件、结果、边界与来源；标题、文件名和目录行不合格 |
| 当前状态和入口 | 当前裁决、阶段、下一步、关键资料与原子的真实引用 | 项目快照可以找到本轮资料，当前投影不继续冒用旧裁决；旧事件保持历史 |

原文与摘要都可有用。用户指定保留全文时，摘要只能作为调用层，不能替换原文。普通笔记不强制原子化，资料文档也不冒充已完成知识编译。

## 先发现，再差量写入

1. 先读项目快照、既有中枢和相关资料，按本轮任务确定范围；全部读取要求不受摘要窗口大小限制，截断后继续取详情。
2. 对照来源与当前记录，选择复用、补录、修订或冲突保留。不以关键词相似判重复，不用更新日期替代裁决依据。
3. 为要修改的既有文档保留恢复点，按稳定块 ID 追加或更新；包含属性、引用、AV的文档不整篇覆盖。追加结果未知时先按回执或稳定来源身份查孤儿块，不盲目重试。
4. 写后回读全文、属性、真实引用和项目入口。同一来源与版本再次执行，应复用既有对象；正文、原子和事件各自查重。

纯新增、尚不存在的资料文档，先按来源身份与已有记录查重，再创建并回读；不要求为不存在的目标或未修改的中枢建快照。恢复依据是本轮新建回执、稳定 ID 和来源，结果未知先查对象。仅保存资料不强制编译原子、登记会话或修改项目状态；需要修改既有入口或正文时，该部分仍受恢复点门约束。来源绑定和溯源缺口分别列明，不能因此冒充整个编译完成。

## 可发现的资料身份

完整资料文档使用 `custom-source-role=source-document`；资料总入口使用 `custom-source-role=source-entry`。它们是资料角色，不新增知识原子类型。用 `custom-source-project-id` 明确所属项目；读取既有记录时可使用 `custom-provenance-project-id`，两者不一致先报告冲突，不猜归属。

来源使用既有 `custom-source-manifest`、`custom-source-path`、`custom-source-hash`、`custom-source-checked` 或 `custom-source-url`，按来源实际填写；人可见的本地入口用已核实的完整绝对路径和可点击链接，机器清单保留项目相对路径、范围和机器哈希。不能手造 revision、hash 或核验时间来凑字段，也不重写原文中的历史路径。

未登记的新工作区不能偷偷替换既有项目源。已获授权且实际读到的正文可以保存为资料副本，同时列明来源接续缺口；不能宣称已完成受控来源绑定或复现验证。

## 验证等级

- `draft`：尚待来源核对或存在未解决问题。
- `source-checked`：已与来源核对；不表示重新运行过分析或证明成立。
- `execution-verified`：有实际执行记录和 `custom-verification-evidence`。
- `evidence-verified`：有对应证据核对记录和 `custom-verification-evidence`。

强验证状态下不能清空证据字段。非空证据字段只是可追溯入口，还要读取并判断它能支持什么；来源自己写“已闭环”，不能据此升级状态。历史缺口只报告和按已授权范围修复，不批量伪造证据或降级。

## 新旧裁决和会话

用户核准的新裁决写入当前状态，并通过真实引用指向依据；旧事件与旧稿保留，明确被何种裁决接替。资料正文不塞进进度页，进度事件只保留摘要和引用。来源会话与编译会话分别记录，写入前捕获真实会话，不在完成后挑最新 rollout 冒充调用者。

本轮受资源限额影响而未完成的来源、版本和对象进入持久待办。下一轮既检查来源变化，也检查尚未验收项；文件哈希不变不能证明编译已经完成。维护报告要说明接续哪一批，不能只列本轮新增名称数量。

## 内容与自然任务验收

动笔前看 [正负例](recording-examples.md)。写后至少用本次任务的自然问题，从项目入口发现资料再读原文，检查能否正确接续。不得先把内部 name 告诉测试会话，再把唯一命中当作冷启动发现成功。

交付分别报告全文保存、知识编译、当前状态接续，以及未完成／冲突／失败项和恢复位置。测试不自动增加或删除原始研究材料；教学任务另读教学参考，保留教学完整性。
