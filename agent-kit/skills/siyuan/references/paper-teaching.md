
# 思源原子化论文教学

## 一、先想清楚什么是“讲解”

**一张卡就是老师站在讲台上，把这个概念从头到尾讲完的一堂小课。**

- 老师讲“标准差”，不会说“请先去看方差，再去看离均差，案例见场景01”。老师会说：我们从一组数开始，先算均值，再算每个人比均值高多少，再平方、平均、开方，一步一步算给你看。
- 原子化管理的是**地址**：让学生悬停一个词，就弹出这一堂完整的课。原子化不是把知识拆散，再指望学生用鼠标把点连成线。
- 虚拟引用和显式链接的作用，是学生**读完之后**遇到相邻概念时，可以点一下再温习。它是加深，不是承载。卡内的任何一个字，都不得靠“见X”“同场景”“如前所述”“参见”把内容外包给别处。

每个知识点必须同时做到三个“完整”：

1. **完整的概念讲解**：这个概念回答什么问题，是什么，怎么读，什么时候用，用错会怎样。
2. **完整的案例呈现**：数据表、逐步计算、日常话读法，全部写在这张卡里。不得要求学生跳到某个场景去看数据。
3. **完整的概念关系**：这个概念用到的前置概念，在卡内重新讲一遍并用本卡数据重新算一遍；与相邻概念（前一个、后一个、容易混的）的关系，在卡内用数字讲明。不得让学生点链接去弄明白。

**重复是教学方法，不是缺点。** 同一个概念在十张卡里出现，就在十张卡里各讲一遍、各算一遍。重复的部分有虚拟引用帮学生进一步加深，但引用不能替代这一遍重讲。禁止以“去重”“精炼”“减少重复”为由删除讲解。

**学生视角检验（每张卡写完必须做）：** 假装你没读过任何别的卡，只读这一张。
1. 每个词都被解释了吗？
2. 每个数字都能在本卡里找到来历吗？
3. 不翻别处，能做对本卡的自测题吗？
4. 读完能不能自己说清它和相邻概念是什么关系？
任何一条答“不”，这张卡就没写完。

## 二、一张概念卡的写法（顺序即教学顺序）

1. **名称段**：中文主名、英文全称、缩写、记号、读音；列出同一概念的所有其他叫法（如预测变量＝自变量＝解释变量＝协变量），声明本课堂统一用哪个名字。英文和同义叫法放在最前面。
2. **它回答什么问题**：用一个生活情境提出问题（两个班平均分一样，为什么感觉不一样？），让学生先有“为什么要学它”的动机。
3. **一句话定义**，紧接着承诺“下面用一组数从头算一遍，不需要你事先会前面的概念”。
4. **完整案例**：给出数据表；把用到的每一个前置概念，用这组数据**当场重新讲、重新算**（均值是什么，算一遍；离均差是什么，算一遍……）；每步写出中间算式；最后用日常话读出结果。
5. **概念关系**：这个概念从哪里来、往哪里去，用同一组数字把链条算通（离均差→平方→方差→标准差→协方差→相关系数）；与容易混淆的概念并排对照。
6. **换个角度再讲一遍**：换一组数做对照（平均相同、分散不同），或换一个变换（整体乘2、整体加5）看它怎样变，加深理解。
7. **在论文里怎样用**：把论文里用到它的那一处讲明白；用到的符号和概念，在这里再讲一遍，不假定学生记得。
8. **容易混淆的点**：每点配一个数字例子，不用抽象否定句。
9. **自测题与完整解答**：每题写出推理过程，不是只给答案。
10. **结尾**：用普通文字说“接下来可以学……”（学生遇到这些词会自动弹出引用）。不放目录式链接，不露出 内部机器名称 内部名称。场景页面只作为可选的“想自己拖着滑块试一试”，且卡内案例已经完整。

机制卡（推导）：先说要算什么、为什么需要；逐个定义字母、时间、单位；一行一行推导；用具体数字完整代入；用第二种算法核对；自测带解答。
场景卡：问题；把所需概念重讲；数据表；逐格计算；复述结论；对照或反例；练习。HTML 只是附加的可操作资源，页面里也保留表和手算。
逐句精讲：原文与出处；翻译；逐短语解释；本句涉及的每个概念和符号从头讲一遍、用具体表格算一遍；完整推理；与上下句的关系；带解答的练习。精讲读完，学生不点任何链接就能跟上。

## 三、必须避免的写法

- 用“见X”“同场景01”“同前”“如上”“参见”指代内容；
- 要求学生点链接或跳到场景才能看到数据；
- 用学生尚未学过的高阶概念做基础概念的例子（用随机截距讲标准差）；
- 相邻几张卡各用一套数字，破坏一条数据链；
- 只给公式不给数字、只给结论不给过程；
- 新概念突然涌入（讲基础卡时抛出 W、H、p₁₁）；
- 否定句（不是、不证明、不表示）多于正面讲解；
- 目录式结尾；链接显示机器名；
- 为了“精炼”缩水：每次改写后逐卡对比字数，缩水必须补回；
- 公式后夹零宽字符。

## 四、正例与负例（动笔前必读）

完整正负例见 `paper-teaching-examples.md`。公开示例包括只给定义、用未知概念解释基础概念、堆字数却外包讲解三种失败，以及标准差和预测残差两篇完整示范。对具体论文建立卡片时，使用本轮已授权并核对的原文，不把公开教学示例当作论文证据。

## 五、数据链与术语

- 相邻卡片使用同一条已核算的教学数据链，并在每张卡重新给出数据、前置概念与计算过程。具体数字按当前课程确定，不把其他项目的算例或结论直接带入。
- 先列“主名—别名—前置概念”。同义叫法写在卡首；不同层级的概念分别成卡，但关键关系仍在卡内重讲。
- 宽泛别名先用 `search.check_anchor` 预检；污染虚拟引用时按契约处理排除。
- 教学区和课程范围先从当前工作区发现；通过正式引用连接已核验的项目知识，不把教学设数当研究结果。
- 教学卡围绕一个可独立检索的问题，篇幅服从教学完整性；不能把多主题大块与单主题完整教学混为一谈。

## 六、场景资源与 HTML

- 场景是**附加资源**，用来让学生自己拖一拖、改一改。卡内案例必须完整，不得依赖场景才能读懂。
- 用 `answer-me-with-html` 技能生成（`~/.codex/skills/answer-me-with-html/`，`node scripts/am.mjs render`）。稿件 `template: doc`、`theme: shadcn`、`lang: zh`；交互放进 `html` 围栏块，自成一体、不加载外部资源。页面内保留数据表和手算；生成后用无头 Chrome 读回 DOM 核对数字。
- 产出复制到思源 `data/assets/`，场景原子用 iframe 嵌入。场景原子须有 name、alias（含“场景0X”这类学生会写的叫法）、`custom-teaching-type=scenario`、draft；先盘点已有场景，不重复建设。

## 七、执行与验收

1. 动笔前读 `paper-teaching-examples.md`。完整读取授权范围，按稳定 ID 建账本。
2. 写入前留恢复点（时间线；时间线不可用时用本地全保真 kramdown 备份并说明）。含 name/alias/custom-*/引用/AV 的文档禁止整篇覆写，只做块级修改；严格预检后写入。
3. 新增或转移 name/alias 先 `check_anchor`；不静默挑候选。
4. 写入后：按块 ID 回读属性与全文；独立核算所有算术（脚本）；**逐卡量字数，不低于改前**；做“学生视角检验”；检查有无“见X”“同场景”内部机器名称、零宽字符。
5. 界面实测至少一条跨层嵌套链：先看首屏是否回答触发词，再点到下一层。不能用工具的精确检索冒充编辑器虚拟引用。
6. 汇报只能写已验证的内容：改了多少、哪些没改、回读与实测证据、恢复点。老师写完不等于学生学会，是否有效由学生反馈判断。

## 八、交付判据

每张卡：学生视角四问全答“是”；案例与前置概念全部在卡内；相邻概念的关系用数字在卡内讲明；有换角度的对照；自测带完整解答；无外包式指代；篇幅不低于改前；属性与别名完好；算术独立核算一致。全量任务按稳定 ID 列出每张卡的处理与回读状态，抽样不能代替逐张。
